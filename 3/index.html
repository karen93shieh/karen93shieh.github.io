Project 3: (Auto)stitching and Photo Mosaics

Image registration, projective warping, resampling, and compositing to create image mosaics (panorama).

  • Date: Oct 2025
  • Course: CS180

Project Overview

This project explores image mosaicing by implementing homography recovery, projective warping, and image blending from scratch. I shot photographs with projective transformations, computed homographies using point correspondences, implemented two interpolation methods (nearest neighbor and bilinear), and create mosaics using Laplacian blending.

This project is spearated into two parts: Part A uses manual selection of point correspondences, while Part B uses Harris corner detection. Currently, Part A is completed, while Part B is in progress.

A.1 — Shoot and Digitize Pictures

Image Acquisition

Per the project description, I shot 3 images with projective transformations that are interiors of buildings (for easy corner selection). The images are shot with a phone, at a timeframe that's less than 5 seconds apart. The overlap percentage is around 70% for each image.

Projective Transform Analysis

For each pair of images, I fix the center of project (COP) and rotate my camera while capturing the images. This ensures that the COP is the same for each pair of images.

A.2 — Recover Homographies

Point Correspondence Selection

I selected around 20-30 point correspondences between the image pairs using the link provided in the project description. The correspondences were chosen to be well-distributed across the overlapping region so that the homography is calculated with less error. Homography Computation

I implemented the computeH(im1_pts, im2_pts) function to solve for the 3×3 homography matrix H using the system of equations Ah = b, where h contains the 8 unknown entries of H. 

def computeH(im1_pts, im2_pts):
    # 1) Inputs: im1_pts = [(x1, y1), ...], im2_pts = [(u, v), ...]
    # 2) Build A by adding two rows per correspondence:
    #    [x1, y1, 1, 0, 0, 0, -u*x1, -u*y1]
    #    [0,  0,  0, x1, y1, 1, -v*x1, -v*y1]
    # 3) Build b by stacking targets: b = [u1, v1, u2, v2, ..., uN, vN]^T
    # 4) Solve least squares h = argmin ||A h - b||  (8 unknowns)
    # 5) Append scale term: h9 = 1 → h = [h1..h8, 1]
    # 6) Reshape to 3x3: H ← reshape(h)
    # 7) Return H

u = (h₁x + h₂y + h₃) / (h₇x + h₈y + 1)

v = (h₄x + h₅y + h₆) / (h₇x + h₈y + 1)

I selected 20+ pairs of correspondences for each image pair, and used least squares to solve for the homography matrix. The reason for not selecting only 4 pairs of correspondences is because I (human) do not have perfect precision in selecting the points, and any errors in the point selection will be amplified in the homography matrix. Having more pairs of correspondences and using least squares will help to reduce the error in the homography matrix.

A.3 — Warp the Images

Warping Implementation

I implemented two warping functions using inverse warping to avoid holes in the output image: 

def warpImageNearestNeighbor(im, H):
    # 1) Invert the homography: map output -> input
    # 2) Get input image size; create an output image of same size
    # 3) For each output pixel (i, j):
    #    a) Compute source homogeneous coord p = H_inv * [j, i, 1]^T
    #    b) Dehomogenize: (x, y) = (p_x / p_w, p_y / p_w)
    #    c) Round (x, y) to nearest integer
    #    d) If inside input bounds, assign output[i, j] = input[round(y), round(x)]
    # 4) Return output

def warpImageBilinear(im, H, output_size=None):
    # 1) Invert the homography: map output -> input
    # 2) Determine output size (given or same as input)
    # 3) Create an empty floating-point output image
    # 4) For each output pixel (i, j):
    #    a) Compute source homogeneous coord p = H_inv * [j, i, 1]^T
    #    b) Dehomogenize to (x, y) in input space (float)
    #    c) Find neighbors: x0=floor(x), x1=ceil(x), y0=floor(y), y1=ceil(y)
    #    d) If any neighbor is out of bounds, continue
    #    e) Compute bilinear weights using dx = x - x0, dy = y - y0
    #    f) value = I[y0,x0]*(1-dx)*(1-dy) + I[y0,x1]*dx*(1-dy)
    #             + I[y1,x0]*(1-dx)*dy     + I[y1,x1]*dx*dy
    #    g) Assign output[i, j] = value
    # 5) Return output

Interpolation Comparison

The nearest neighbor interpolation is faster than the bilinear interpolation (for the three images, the nearest neighbor interpolation took around 22 seconds, while the bilinear interpolation took around 52 seconds), but the bilinear interpolation is more accurate and smoother. One can clearly see that with the nearest neighbor interpolation method, the shadows are chunky (not smooth), while for the bilinear interpolation, the shadows are smooth.

A.4 — Blend Images into a Mosaic

Mosaic Creation Process

With all the methods implemented, I can now create a mosaic. From Project 2, I implemented a Laplacian stack blending method. I reused the code here and blend the images together after the warping.

Weighted Blending

Used weighted averaging to reduce edge artifacts. Alpha values were set to 1 at the center of each (unwarped) image and fell off linearly to 0 at the edges.
