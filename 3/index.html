Project 3: (Auto)stitching and Photo Mosaics

Image registration, projective warping, resampling, and compositing to create image mosaics (panorama).

  • Date: Oct 2025
  • Course: CS180

Project Overview

This project explores image mosaicing by implementing homography recovery, projective warping, and image blending from scratch. I shot photographs with projective transformations, computed homographies using point correspondences, implemented two interpolation methods (nearest neighbor and bilinear), and create mosaics using Laplacian blending.

This project is spearated into two parts: Part A uses manual selection of point correspondences, while Part B uses Harris corner detection following the approach described in Multi-Image Matching using Multi-Scale Oriented Patches.

Part A — Manual Stitching

This section documents manual correspondence selection and homography-based mosaicing.

A.1 — Shoot and Digitize Pictures

Image Acquisition

Per the project description, I shot 3 images with projective transformations that are interiors of buildings (for easy corner selection). The images are shot with a phone, at a timeframe that's less than 5 seconds apart. The overlap percentage is around 70% for each image.

Projective Transform Analysis

For each pair of images, I fix the center of project (COP) and rotate my camera while capturing the images. This ensures that the COP is the same for each pair of images.

Homography Computation

I implemented the computeH(im1_pts, im2_pts) function to solve for the 3×3 homography matrix H using the system of equations Ah = b, where h contains the 8 unknown entries of H. 

def computeH(im1_pts, im2_pts):
    # 1) Inputs: im1_pts = [(x1, y1), ...], im2_pts = [(u, v), ...]
    # 2) Build A by adding two rows per correspondence:
    #    [x1, y1, 1, 0, 0, 0, -u*x1, -u*y1]
    #    [0,  0,  0, x1, y1, 1, -v*x1, -v*y1]
    # 3) Build b by stacking targets: b = [u1, v1, u2, v2, ..., uN, vN]^T
    # 4) Solve least squares h = argmin ||A h - b||  (8 unknowns)
    # 5) Append scale term: h9 = 1 → h = [h1..h8, 1]
    # 6) Reshape to 3x3: H ← reshape(h)
    # 7) Return H

A.3 — Warp the Images

Warping Implementation

I implemented two warping functions using inverse warping to avoid holes in the output image: 

def warpImageNearestNeighbor(im, H):
    # 1) Invert the homography: map output -> input
    # 2) Get input image size; create an output image of same size
    # 3) For each output pixel (i, j):
    #    a) Compute source homogeneous coord p = H_inv * [j, i, 1]^T
    #    b) Dehomogenize: (x, y) = (p_x / p_w, p_y / p_w)
    #    c) Round (x, y) to nearest integer
    #    d) If inside input bounds, assign output[i, j] = input[round(y), round(x)]
    # 4) Return output

def warpImageBilinear(im, H, output_size=None):
    # 1) Invert the homography: map output -> input
    # 2) Determine output size (given or same as input)
    # 3) Create an empty floating-point output image
    # 4) For each output pixel (i, j):
    #    a) Compute source homogeneous coord p = H_inv * [j, i, 1]^T
    #    b) Dehomogenize to (x, y) in input space (float)
    #    c) Find neighbors: x0=floor(x), x1=ceil(x), y0=floor(y), y1=ceil(y)
    #    d) If any neighbor is out of bounds, continue
    #    e) Compute bilinear weights using dx = x - x0, dy = y - y0
    #    f) value = I[y0,x0]*(1-dx)*(1-dy) + I[y0,x1]*dx*(1-dy)
    #             + I[y1,x0]*(1-dx)*dy     + I[y1,x1]*dx*dy
    #    g) Assign output[i, j] = value
    # 5) Return output

Interpolation Comparison

The nearest neighbor interpolation is faster than the bilinear interpolation (for the three images, the nearest neighbor interpolation took around 22 seconds, while the bilinear interpolation took around 52 seconds), but the bilinear interpolation is more accurate and smoother. One can clearly see that with the nearest neighbor interpolation method, the shadows are chunky (not smooth), while for the bilinear interpolation, the shadows are smooth.

A.4 — Blend Images into a Mosaic

Mosaic Creation Process

With all the methods implemented, I can now create a mosaic. From Project 2, I implemented a Laplacian stack blending method. I reused the code here and blend the images together after the warping.

To create the mosaic, I first shot two images with projective transformations, and then used the homography matrix to warp the images. The interpolation method I used is the bilinear interpolation. The canvas for the images are "extended" (appended with a bunch of black pixels surrounding the original image) so that the images can be stitched together. Then, I blended the images together using the Laplacian stack blending method, adjusting the layers so the edges are not visible.

Blending Analysis

The blending results are smooth, and the edges are not visible. The Laplacian blending method is able to blend the images together by taking the high frequency and low frequency of the images, and blending them together.

Part B — Automatic Feature Matching and Stitching

The goal of this part is to automatically stitch images into mosaics by detecting corners (features), finding the descriptors, matching the descriptors across images, estimating homographies with RANSAC, and combining the images into a mosaic using Laplacian blending. The pipeline follows Brown et al., "Multi-Image Matching using Multi-Scale Oriented Patches" (with simplifications and assumptions).

B.1 — Detecting Corner Features (Harris + ANMS)

Corner Detection (Harris)

We use Harris for corner detection. The intuition of Harris's algorithm is using the fact that the change in both x, y value is big at a corner (big derivative). Hence, if we find the location that has big change in x and y, we are probably at a corner. In this project, we use the simple assumptions that the image is not rotated, and we do not implement multi-scale.

Adaptive Non-Maximal Suppression (ANMS)

After having a collection of points from the corner detection algorithm, I use ANMS to have a relatively equal distribution of corners in the image. In this way, the corners are well spreaded out, and makes computing H more accurate (because there is representations for the entire picture, and not just at the locations where there are strong signals for corners).

The way the ANMS work is that for each corner point, we find the minimum distance to any other corner point that has a high corner response (intensity) by some constant factor (c_robust, which is 0.9 in the paper). We then sort the corners by the mininum radius (descending order, so the biggest radius go first), and pick the top target_num coordinates. This ensures that we select corners that are both strong and well-distributed across the image. 

def find_ANMS(intensity, coords, c_robust=0.9, target_num=500):
    # 1) Inputs: intensity = all intensity calculated from Haris, coords = corner coordinates
    # 2) Initialize: n = number of corners, vals = intensity values at corner locations
    # 3) Initialize: r = array of minimum distances (initially infinity)
    # 4) For each corner i:
    #    a) Find all corners j where vals[i] < vals[j] * c_robust 
    #    b) If any stronger corners exist:
    #       - Compute squared distances between the points (i to any j)
    #       - Find minimum distance: r[i] = mininum radius (squared distance)
    # 5) Select top target_num corners with largest r values
    # 6) Return selected corner coordinates

B.2 — Feature Descriptor Extraction

Feature Descriptor

After getting a collection of well-spreaded corners, the next thing to do is to "describe" the corners. Using method mentioned in Brown et al.'s work, I extracted a 40x40 patch surrounding the corner pixel, downsample it, and normalize the value. B.3 — Feature Matching

Feature Matching

After getting the descriptors from B.2, we now need to match them across the two different images. Here, we used Lowe's trick, where for every 8x8 patch in the first image, we find the 2 closest 8x8 patches on the second image (kNN with k=2, and metric being Euclidean). Then, we compare the ratio of the 1-NN and 2-NN. If the ratio is smaller than some threshold (0.5 in this case), we say that the patch in image 1 matches with the 1-NN. If the ratio is bigger than the threshold, we reject the pairing (and that corner gets removed from the list of corners).

The intuition behind Lowe's trick is that if there's one match that's really, really good, the ratio between 1-NN/2-NN would be really small (since 1-NN would be small, and 2-NN would be big). If there are two matches that are equally good, it means neither of them are actually good, and the ratio would be closed to 1.

B.4 — RANSAC for Robust Homography

RANSAC

The idea of RANSAC is with n iterations, select 4 pairs of points at random and compute the homography matrix H, and based on that H, calculate how many inliers existed (inlier is defined as when applying H to coordinates [of one image], the resulting coordinate is within eplison of the actual coordinate [of the other image]). The H with most inliers are kept. After the n iterations, we use all the inliers associated with the best H to recompute H_final, and that is final homography matrix H. 

def RANSAC(matches, n, eplison):
    # 1) Repeat n times:
    #    a) Pick 4 random pairs
    #    b) Compute H from these 4 pairs
    #    c) Count how many matches H explains well (inliers)
    #       i) Keep the longest list of inliers
    #       ii) Keep the H with most inliers
    # 2) Recompute H using the longest list of inliers inliers
    # 3) Return final H
